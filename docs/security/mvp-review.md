## 1. 계획 체크리스트 (PRD 14장 T1-29)

| # | 항목 | 결과 | 근거 |
|---|---|---|---|
| 1 | 평문 디스크 기록 | ⚠️ 조건부 통과 | 뷰어는 디스크에 쓰지 않음(E2E에서 저장소·OS 임시 폴더 전수 검색으로 확인). 서버는 패키징 전 원본을 저장소에 잠시 보관하고 패키징 후 삭제(NFR-S8), 워커는 Office 변환 중 소유자 전용 임시 파일을 쓰고 즉시 삭제. 서버 측 평문 보관은 설계상 의도 |
| 2 | 로그 민감정보 | ✅ 통과 | pino에서 Authorization·Cookie 마스킹, 요청 본문 미기록, 감사 로그 detail은 민감 키 재귀 마스킹(테스트), 오류 응답에 내부 상세 미포함 |
| 3 | 클라이언트 측 기간 판정 | ✅ 통과 | 기간·수신자·회수 판정은 서버 정책 엔진만 수행. 뷰어는 서버가 준 유효 기간(issuedAt~expiresAt)으로 재발급 시점만 계산 |
| 4 | 라이선스 재사용 | ✅ 통과 (잔여 위험 있음) | 라이선스는 기기·문서·licenseId에 바인딩(HKDF info), 서명 검증, 10분 수명. 다른 기기·다른 문서에서 재사용 불가(테스트). 잔여 위험은 §3 R1 참고 |
| 5 | 기기 키 보관 | ✅ 통과 (잔여 위험 있음) | X25519 개인키를 Electron safeStorage(DPAPI)로 암호화해 사용자 프로필에 저장. 다른 Windows 계정에서 복사하면 복호화되지 않음(테스트). 잔여 위험은 §3 R2 참고 |

## 2. 점검 중 발견해 수정한 문제

| # | 문제 | 위험 | 조치 |
|---|---|---|---|
| F1 | OTP 요청 응답 시간이 수신자 여부에 따라 달랐음 (등록된 수신자만 DB 기록·SMTP 발송 후 응답) | 응답 시간 측정으로 수신자 목록 추정 가능 (요구사항 "계정 존재 비노출" 위반) | 수신자 판정·발송을 응답 이후 백그라운드로 처리, 항상 즉시 202. 테스트 추가 |
| F2 | `trust proxy`가 항상 켜져 있었음 | 프록시 없이 운영 시 `X-Forwarded-For` 위조로 OTP IP 한도 우회·감사 로그 IP 오염 | `TRUST_PROXY_HOPS` 환경 변수(기본 0)로 변경 |
| F3 | `.drm` 다운로드·거부가 감사 로그에 남지 않았음 (E2E에서 발견) | 유출 조사(S7) 시 추적 공백 | `DOCUMENT_DOWNLOADED`, `DOCUMENT_DOWNLOAD_DENIED` 이벤트 추가(마이그레이션 포함) |
| F4 | API 응답에 보안 헤더 없음 | MIME 스니핑, 프레이밍, 토큰 응답 캐시 | nosniff, X-Frame-Options, CSP, Referrer-Policy, CORP, `Cache-Control: no-store`, 운영 HSTS. 테스트 추가 |
| F6 | 암호·손상 PDF를 패키징 단계에서 걸러내지 못했음 (수신자가 열 때 실패) | 열 수 없는 문서 배포 | 워커가 pdf.js로 실제로 열어 검사, 암호·손상·빈 문서·512MB 초과를 사유와 함께 FAILED 처리 (Office 변환 결과에도 적용) |
| F5 | 포털에 CSP 없음 (refresh 토큰이 sessionStorage에 있음) | XSS 발생 시 토큰 외부 유출 용이 | 운영 빌드에 CSP 삽입(외부 스크립트·외부 연결 차단) |

## 3. 잔여 위험 (수용 또는 후속 단계)

| # | 위험 | 설명 | 대응 계획 |
|---|---|---|---|
| R1 | 이미 받은 CEK의 영구 사용 | CEK는 문서마다 고정입니다. 변조된 뷰어나 메모리 덤프로 CEK를 꺼내면, 회수·만료 후에도 해당 `.drm`을 복호화할 수 있습니다. | DRM의 본질적 한계. 가시 워터마크로 추적, 4단계 포렌식 워터마크·고등급 문서 래스터 전송, 외부 모의해킹(T4-08) |
| R2 | 같은 Windows 사용자 권한의 악성코드 | DPAPI는 다른 사용자로부터 보호하지만, 같은 사용자 권한으로 실행되는 프로그램은 기기 키를 풀 수 있습니다. | 2단계 이후 TPM 기반 키 보관 검토 |
| R3 | 화면 촬영·캡처 우회 | `setContentProtection`은 OS 캡처 API만 막습니다. 카메라 촬영, 가상 머신, 원격 데스크톱 클라이언트 측 캡처는 막지 못합니다. | 워터마크로 추적. 원격 세션 탐지는 후속 검토 |
| R4 | 서버의 평문 원본 일시 보관 | 업로드부터 패키징 완료까지 원본이 저장소(로컬 디스크)에 평문으로 있습니다. | 운영 저장소는 디스크 암호화·접근 통제 필수. 2단계에서 업로드 즉시 암호화(임시 키) 검토 |
| R5 | 로컬 파일 키링 | 개발용 KMS·서명 키링은 평문 파일입니다. 운영 모드(`NODE_ENV=production`)에서는 기동을 거부합니다. | T2-10 운영 KMS(Vault/AWS KMS) 구현 전 운영 배포 불가 |
| R6 | 발신자 로그인 잠금은 이메일 단위 | 여러 계정을 번갈아 시도하는 공격(credential stuffing)은 IP 단위로 막지 않습니다. | 운영 앞단(WAF·리버스 프록시)에서 IP 속도 제한, 2단계 SSO 도입 |
| R7 | 포털 refresh 토큰 sessionStorage 보관 | CSP로 위험을 줄였지만 XSS 시 탈취 가능합니다. | 2단계 SSO 도입 시 httpOnly 쿠키 + CSRF 토큰 방식으로 전환 검토 |
| R8 | 코드 서명 미적용 | 현재 설치 파일은 서명되지 않아 SmartScreen 경고가 뜨고, 변조 여부를 사용자가 확인할 수 없습니다. | 파일럿 전 코드 서명 인증서 발급, CI 비밀값으로 주입 |
| R9 | ~~실제 Office 변환 미검증~~ | 해결: 실제 Gotenberg로 DOCX·XLSX·PPTX 변환과 한글 보존을 자동 테스트로 검증, E2E에 Office 배포·열람 시나리오 추가 | 사내 실제 문서(복잡한 서식·글꼴)로 파일럿에서 품질 확인 |

## 4. 확인된 보안 통제 요약

| 영역 | 통제 | 검증 |
|---|---|---|
| 암호 | AES-256-GCM STREAM(청크 순서·절단·꼬리 탐지), X25519-HKDF-A256KW, Ed25519 도메인 분리 서명, RFC 3394 벡터 | 단위 테스트 57건 |
| 키 관리 | 문서별 CEK, KMS 봉투 암호화(docId 문맥 바인딩), 키 교체, CEK 사용 직후 0으로 덮어쓰기 | 단위·통합 테스트 |
| 인증 | argon2id, 계정 존재 비노출, JWT 유형 분리, refresh 회전·재사용 탐지, OTP HMAC 저장·시도 횟수 원자적 제한 | 통합 테스트 |
| 정책 | 서버 단독 판정, 회수 우선, 반개구간 기간, advisory lock으로 기기 수·열람 횟수 동시성 보장 | 경계값·동시성 테스트 |
| 감사 | append-only DB 트리거, 같은 트랜잭션 기록, 민감정보 마스킹 | 통합 테스트 |
| 뷰어 | contextIsolation·sandbox, IPC 출처·입력 검증, CSP(렌더러 네트워크 차단), 캡처 차단, 단축키 차단, 퓨즈(RunAsNode 등) | 설정 테스트 + 패키징 결과 판독 |
